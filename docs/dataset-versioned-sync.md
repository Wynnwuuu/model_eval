# ManuEval 评测集版本化同步

## 数据身份

- 同步使用精确字段 `case_id + variant_label` 作为业务身份。
- `case_id` 必填，`variant_label` 可为空；组合必须在源快照中唯一。
- 当前评测集若已经存在重复组合，预览会阻断并列出当前行号，避免静默选择其中一行继承结果。
- 已存在的组合保留 `__datasetItemId`。删除后再次出现时，恢复最近历史版本中的稳定 ID 和平台结果。
- 源列名、顺序和值是当前版本的结构来源。同步不做模糊列名推断。
- 身份列名必须精确为 `case_id`；平台不会静默去除列名空格或把近似列名改写为身份列。即使来源没有数据行，缺少该列也会阻断应用，避免误删全部 case。
- `__` 前缀保留给 ManuEval 稳定 ID 和审计元数据，源表不能创建或覆盖这类列。

## 同步来源

- 飞书 Base：服务端使用自建应用 `tenant_access_token` 读取整张表。链接中的 `view` 不参与筛选。
- 手动来源：CSV、TSV、JSON 文件或粘贴内容。
- 从飞书粘贴的制表符数据按表头识别为 TSV；Prompt 中的普通逗号不会被误当作分列符。
- 飞书 Base 需要应用权限 `bitable:app:readonly`，并需要把该应用添加为 Base 协作者。
- 同步不回写飞书，也不在后台自动执行。

## 预览和应用

1. 用户选择来源并生成预览。
2. 服务端校验身份唯一性，按稳定 ID 计算新增、更新、删除、恢复和不变 case。
3. 用户指定新列是否为模型结果，并逐结果列选择合并策略。
4. 应用前，飞书 Base 会重新读取并比较快照哈希；数据集版本也会再次校验。
5. 应用只生成一个新的数据集版本，然后复用现有任务/投票传播逻辑。

结果列策略：

- `preserve_platform`：保留已有平台结果，源表只为新 case 提供结果。
- `fill_platform_blanks`：平台结果为空时使用源表结果。
- `source_overwrite`：源表覆盖平台结果，包括用空值清除结果；界面要求二次确认。

源表没有的既有结果列、结果伴随列和系统审计字段不会被删除。普通业务列以源表为准。

## 结果新鲜度

- 每个结果列在隐藏字段 `__generationResultMeta` 中记录来源、依赖列、输入指纹和陈旧状态。
- 生成相关输入发生变化且结果被保留时，结果标记为“输入更新后未重新生成”。
- 普通元数据变化不标记陈旧。
- 成功生成回填会更新该结果的输入指纹并清除陈旧状态；若生成期间输入已变化，回填结果仍会明确标记陈旧。
- 旧结果没有指纹时，使用数据集的输入、参考素材和标准生成参数列进行保守比较。

## 并发规则

- 同步和生成批次创建都先锁定 `datasets` 当前记录。
- 预检后数据集版本变化，旧预检不能创建生成批次。
- 运行中或等待回填的生成任务只在以下同步变更时阻断：删除所选 case、修改该任务引用的输入列、修改目标结果列。
- 仅修改无关元数据或新增无关 case 不阻断运行任务。

## 表格显示

- 结果列和系统列首次默认隐藏，用例 ID 始终显示。
- 可以逐列显示/隐藏，也可以展开或折叠全部结果列。偏好按评测集保存在浏览器本地。
- 列菜单支持单列升序、降序和清除排序。排序按值类型稳定执行，空值始终在末尾。
- 排序只影响当前视图；下载、保存、任务传播和生成 case 顺序仍使用源顺序。
