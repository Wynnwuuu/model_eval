# 提交后揭示开关设计

## 目标

在正式评测页顶部提供“提交后揭示模型”开关，让评委在同一次评测会话中随时选择提交后的流程：

- 默认关闭：保存当前 case 后直接进入下一题；最后一题直接进入结果。
- 开启：保存当前 case 后停留原位、揭示实际模型名，并允许继续修改模型备注，再由“下一题/查看结果”继续。

## 范围与状态

- 覆盖 A/B、Pairwise、Arena-rank、MOS/Rubric；Benchmark Preview 不展示开关且保持直接前进。
- 开关是评委当前评测会话的临时 UI 状态，不写入任务配置、投票记录、localStorage、HTTP API 或数据库。
- 每次新开始、恢复或重新进入一项评测时恢复为关闭；同一任务的 case 切换期间保留当前选择。
- 开关只决定下一次成功提交后的行为。已经揭示的 case 无法重新匿名；此时切换仅影响后续 case，当前 case 仍通过“下一题/查看结果”完成备注保存和前进。

## 交互

- 统一开关置于正式评测内容上方，在桌面和移动端均可见。
- 关闭文案明确为“提交后直接下一题”，开启文案明确为“提交后揭示模型”，避免与任务本身的“盲测”配置混淆。
- 评测提交、排名、评分、快捷键和移动端提交入口统一读取同一个会话状态。
- 跳过仍直接进入下一题，不揭示、不保存备注；保存失败仍停留当前 case 且不揭示。
- 非盲任务也遵循相同的提交后流程；开启时仍进入复盘阶段，关闭时直接前进。

## 实现边界

- 在 `ModelEvalApp` 维护单一布尔状态，并将当前状态作为共享顶部控件呈现在三类正式评测屏幕外层。
- 现有 `commitVoteRecord` 的显式 `reveal` 选项继续作为唯一分流点；正式评测 handler 从会话开关传值，跳过和 Preview 继续显式传 `false`。
- 不新增公共数据类型、持久化字段、依赖、迁移或外部服务。

## 验证

- Playwright 覆盖默认关闭直接前进、开启后揭示、同一会话跨 case 保持、重新进入恢复关闭，以及已揭示 case 切换不隐藏当前身份。
- 覆盖 A/B、Pairwise、Arena-rank、MOS/Rubric 与移动端；确认 Arena-rank 媒体仍默认暂停。
- 运行相关确定性测试、全部 `test:*`、TypeScript lint、前后端 build、Docker/PostgreSQL API smoke、完整 Chromium E2E 和 `git diff --check`。
